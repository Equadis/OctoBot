# OctoSim MVP — reference implementation status
Development branch only; production remains gated. The planner's public Run Simulation stays disabled.

## Research execution
104 executable rank definitions across nine classes, 84 distinct abilities, including 63 external-only/staging-reference rank definitions. Agony and Doom now replace one another per caster/target, Agony ramps base damage separately from spell power, and Power Word: Shield is compiled with explicit shield and lockout inputs. APS reports actual absorption, not shield capacity. Added Mage AoE, Pyroblast, Blizzard, Priest Holy Fire and Smite, and Warlock damage-linked self-healing. Database and archived changes remain separate for conflicting rank values. Channel application and leech basis require explicit policies; stationary ground effects use the supplied target list. Staging Flash of Light rank 7 and Holy Shock rank 4 are explicitly acknowledged reference inputs; Holy Shock supports one chosen role per rotation and explicit proc-driven cooldown reset probability. Warrior Slam, Mortal Strike, Whirlwind and Cleave and Paladin Consecration have explicit reference models. Consecration uses supplied declining tick multipliers rather than the old constant-tick Turtle formula; unknown live scaling and stance restrictions remain explicit inputs. The actual build compiler uses unrounded sheet values, rank identity and explicit rules. The opt-in reference lab runs one learned spell using a worker; the CLI, adapter and configured-rotation lab run explicitly configured supported rotations. Unsupported actions are rejected, not removed. The phase filter prevents known AQ-book ranks from being selected during BWL. Reference-only phase and learnability still require confirmation on OctoWoW.

External source provenance is attached to each rank. ClassicDB healing rows and a pinned WoWSims Turtle commit are reference values, not live OctoWoW evidence. The Fireball, sting, Backstab and Eviscerate conflicts must be acknowledged. Unknown coefficients and observed costs must be supplied rather than silently imputed.

## Local reference command
Run from repository root:
```sh
node tools/sim/reference-scenario.mjs explicit-scenario.json results.json
```
The JSON contains build, exact gearById, learnedSpellIds, rankByAbility, policies, encounter, optional rows, seed and iterations. See the tests for explicit inputs. The result includes rank provenance, seeded distributions, example combat events and limitations.

## Release blockers
- Complete rank/effect implementation for all registered abilities and actual learnability.
- Live capture verification for cast, damage, resource, hit, crit, cooldown, tick timing and procs.
- Verified missing race/class and companion base data.
- Dynamic class talents, weapon imbues, poisons, pet abilities, trinket swaps, item/set procs, raid aura behaviour, complete tank mechanics, live resource coefficients and automatic mana/energy regeneration and resistances still require implementation and verification. Scripted incoming damage, shields, dynamic swing haste, chained targets, ammunition, combo bleeds, health conversion and periodic consumption now have research runtime support.
- Browser integration has passed CI smoke tests on all nine class planners and both reference workers; actual live combat validation remains outstanding.
No claim of full simulator completion or validated DPS.

Experimental per-hand poison models bind to explicitly eligible damaging physical contacts and white attacks, respect independent weapon charges, explicit resist/crit/application policies, imported Vile/Improved/Efficient Poisons and Vigor talents, Envenom, and shared Deadly Poison stacks. Instant/Deadly/Wound/Agitating damage only; Wound healing reduction, Crippling/Mind-numbing utility effects, force-application attacks and poison rank measurement are outstanding. Single-rank and rotation templates require the explicit model rather than inventing exact current-server numbers.

Seal of Righteousness and Seal of Command are mutually exclusive timed self auras, with explicit white-hit rate/PPM, weapon-basis, scaling, outcomes and threat policies. Judgement consumes the active seal under the explicit cast/landed policy and selects its damage model. The single-rank lab cannot cast Judgement in isolation; use the rotation lab. Directional seal twisting is available only with an explicit encounter.sealTwist policy: windowMs (positive integer milliseconds), swingPolicy ('first' eligible landed damaging main-hand swing or 'all' eligible swings), and pairs (ordered arrays of old and new registered seal ability IDs). The prior seal is not a second active aura, only a temporary proc candidate bounded by its original expiry, the supplied overlap window and consumption of the current seal. This is a research hypothesis; exact live timing, direction, eligibility and proc ordering remain unverified. Utility seals and Judgement debuff refreshing remain outstanding. Crusader Strike now accepts explicit weapon and Holy Spell Power coefficients alongside the official-guide base values; older archived formula variations must not be mistaken for current server observations.

Poison AP inputs now use the current aura-adjusted attack power. Instant effects and new applications scale dynamically; Deadly Poison follows the explicit application snapshot or dynamic tick policy. Synthetic regression cases cover both policies; no live-server AP coefficient has been inferred.

Wound keeps its configured damage and applies healing-received reduction; the strongest concurrent healing reduction is used for direct healing and leech before overheal and effective-healing threat. Crippling/Mind-numbing record movement-speed and cast-time debuffs without artificial damage; they do not yet drive enemy movement or casting. Utilities respect poison resistance/charge rules and forced applications. Utility-only threat is unknown; no coefficient is invented.
