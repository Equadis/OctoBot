# OctoSim MVP — reference implementation status
Development branch only; production remains gated. The planner's public Run Simulation stays disabled.

## Research execution
104 executable rank definitions across nine classes, 84 distinct abilities, including 63 external-only/staging-reference rank definitions. Agony and Doom now replace one another per caster/target, Agony ramps base damage separately from spell power, and Power Word: Shield is compiled with explicit shield and lockout inputs. APS reports actual absorption, not shield capacity. Added Mage AoE, Pyroblast, Blizzard, Priest Holy Fire and Smite, and Warlock damage-linked self-healing. Database and archived changes remain separate for conflicting rank values. Channel application and leech basis require explicit policies; stationary ground effects use the supplied target list. Staging Flash of Light rank 7 and Holy Shock rank 4 are explicitly acknowledged reference inputs; Holy Shock supports one chosen role per rotation and explicit proc-driven cooldown reset probability. Warrior Slam, Mortal Strike, Whirlwind and Cleave and Paladin Consecration have explicit reference models. Consecration uses supplied declining tick multipliers rather than the old constant-tick Turtle formula; unknown live scaling and stance restrictions remain explicit inputs. The actual build compiler uses unrounded sheet values, rank identity and explicit rules. The opt-in reference lab runs one learned spell using a worker; the CLI, adapter and configured-rotation lab run explicitly configured supported rotations. Unsupported actions are rejected, not removed. The phase filter prevents known AQ-book ranks from being selected during BWL. Reference-only phase and learnability still require confirmation on OctoWoW.

External source provenance is attached to each rank. ClassicDB healing rows and a pinned WoWSims Turtle commit are reference values, not live OctoWoW evidence. The Fireball, sting, Backstab and Eviscerate conflicts must be acknowledged. Unknown coefficients and observed costs must be supplied rather than silently imputed.

## Local reference command
Run from repository root:
```sh
node tools/sim/reference-scenario.mjs explicit-scenario.json results.json
```
The JSON contains build, exact gearById, learnedSpellIds, rankByAbility, policies, encounter, optional rows, seed and iterations. See the tests for explicit inputs. The result includes rank provenance, seeded distributions, example combat events and limitations.
